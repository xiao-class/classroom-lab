# 课堂实验动画

把老师说的实验或科学过程做出来。默认交付一个独立 HTML，打开后点播放即可上课；不要把脚本、方案或分镜当作动画交付。

## 一句话开始

用户只给实验名也直接制作。默认中文、经过视觉设计的实验主体、清晰的大字、浏览器播放、约半分钟到一分钟、带普通话讲解；按知识难度推定适合的学段，在交付时用一句话说明即可。用户已给的年级、时长、风格、格式优先。

不要先让老师填年级、配色、尺寸、音色、模型、API Key 或工具选择表。仅当缺失信息会改变实验对象/科学结论、确实无法合理推定时，问一个短问题。实验含糊时可以说明一个合理解释后制作；例如“浮力实验”默认演示浸入体积与浮力，而不是等待完整教案。

尊重用户原始命题。若它科学上有误（如“证明重物一定下落更快”），简短纠正并演示正确的对照，不按错误命题捏造结果。

## 按题目选科学表达

范围包括物理、化学和生物，不以现有示例为白名单。先判断用户要看的是宏观实验、微观机制、生命过程，还是可调模拟；概念过程不强行包装成做过的真实实验。

- 物理：力、光、电、运动等，核对量纲、方向和模型适用范围。
- 化学：先读 [化学制作与核验](references/chemistry.md)，处理宏观现象、粒子机制和符号表达之间的对应关系。
- 生物：先读 [生物制作与核验](references/biology.md)，选定细胞/组织/个体层级，核对结构、阶段和数量关系。
- 跨学科：按本题涉及的机制组合检查，不要求用户先选择学科。

## 制作

1. 在内部明确一个要观察的现象或机制。可调实验明确操纵变量和不变条件；生命过程明确阶段及连续变化。安排“预测→观察→解释”的推进。围绕实验对象发生变化，避免只有文字卡片和装饰动画。没有实际测量时将数值标为模型计算，不能写成实验实测。
2. 查明科学关系和适用范围。读 [科学核验](references/science-check.md)；遇到陌生或不确定的关系，核对教材、大学或科学机构原始资料。没有网络时如实记录依据与未核验项，不伪造引用。知识核验由代理完成，不要求老师先查资料。
3. 先读 [视觉与动效](references/visual-motion.md)，按实验选择表现：实体器材、空间关系适合三维；平面光路、图表及精确读数可用精致的 SVG/Canvas。默认做有质感的实验场景；用短暂运镜、器材入场或变化过程吸引注意，进入观察后稳定视角。用户只给实验名时也由代理完成这些选择，不让老师先选风格。默认单文件、无 CDN、无字体下载、无付费服务、无服务器依赖。可复用 [播放模板](assets/player.html) 和 [构建说明](references/build-contract.md)：代理编写 `lesson.json`、`scene.js` 后运行构建脚本。这些是代理内部文件，不让老师编辑 JSON 或运行命令。没有 Python 时可直接生成自包含 HTML，保留同等操作与检查；不要让老师安装运行时。三维使用随 Skill 提供的本地运行库和场景基础，构建器可内嵌，老师不用安装 Node 或 Three.js。只有制作/维护代理需要处理依赖；视频按实际需求另行导出。
4. 至少提供播放/暂停、重播、分步查看、隐藏/显示结论；画面应能投屏。少量有教学意义的参数才加滑块，参数变化后图形、数值和解释必须一致。不要让老师先选方案才能看到首版。模板允许替换视觉风格，不把配色或分镜数量当作科学要求。
5. 在新的输出目录保存成品和可修改源文件。默认沿用老师上一版继续改；需要改模型时复核结果。不要改 Skill 安装目录里的模板来完成单次课程。

## 检查后交付

实际运行新代码。先核对模型，再检查画面；“HTML能打开”不等于实验正确。

- 用独立手算值检查典型情况、一个边界和一个反例。绘制、数字标签、结论共用同一个状态；不得滑块动了但结论固定。
- 用可用的浏览器工具实际打开最终 HTML，操作播放、暂停、重播、切阶段、改参数、显示结论；检查开始/中间/结束画面、标签遮挡、窄屏和控制区可达性。复用模板也要检查新场景。没有浏览器工具时交付并明确“未完成浏览器实测”，不要声称通过。
- 三维检查镜头落定、器材和数值对应、窄屏可读性、暂停后不再运镜及 WebGL 不可用时的兼容视图。预测阶段在提问讲完并留出思考时间前，不用运动或标签提前揭示答案。
- 自包含结果在断网或禁止外网请求时应正常演示。音频另行说明。涉及播放兼容时，以实际测试过的浏览器为准。
- 只修复实测发现的问题；不为每个简单动画启动复杂测试工程。不确定的科学结论不能用醒目效果掩盖。

交付回复尽量短：**打开动画的链接 + 一句如何使用 + 必要的模型边界**。先展示动画，再把源文件/核验说明作为次级入口。老师可以继续说“慢一点”“给四年级看”“加一个错误示范”来修改。

## 旁白与格式

默认带普通话讲解，同时提供按阶段对应的短讲解稿。先读取 [旁白与导出](references/narration.md)，使用实际可用且已授权的语音能力生成音频并嵌入网页；不先让老师选择声音或配置API。只有用户明确要无声时才省略旁白。没有可用配音能力时，明确说明缺失并先交付可用动画，不能把只有文字稿称为有声完成。

制作旁白或需要视频导出时，读 [旁白与导出](references/narration.md)。网页、录制的视频和可编辑 PPTX 是不同交付，不能把网页说成原生 PPT 动画。
